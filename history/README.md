## 演化逻辑

**第一步（01 → 02）：把训练做稳。**
初始版本的重点是"能不能训出可用的模型"，采用了域自适应自训练提升对未知域的适应。
但多轮自训练带来的收益递减、且难以归因，于是转向"选检查点 + 校准统计量"这种更可控的做法，
得到基线 0.7539。

**第二步（02 → 03）：把优化对象缩小。**
分析发现编码器特征已充分收敛，继续整体微调只会破坏表征。于是冻结主干与特征精炼模块，
只训练 2.67 M 的解码器，并用父模型的软预测作 KL 约束。四段串联，每段只增加训练样本数。
这一段是干净的单变量实验，增益 +0.0071。

**第三步（03 → 04）：把增益榨干。**
继续延长微调至 51200 样本，增益衰减明显（+0.0044 → +0.0036 → +0.0027 → +0.0022），
说明解码器的可优化空间正在耗尽。同时引入 8 路概率平均（多尺度 + 翻转）的测试时增强，
最终达到 0.7668。

## 阅读建议

- 想理解**最终方法**：直接看仓库根目录的 `docs/notes/`，不必读历史版本
- 想理解**为什么这么改**：按 01 → 04 顺序读各阶段的 `README` 与 `evidence/`
- 想**复现某一步**：用对应阶段的 `configs/` 与 `code/`

历史版本中的脚本可能依赖当时的数据布局，未必能直接运行——它们的作用是**记录当时的做法**，
而不是提供可直接执行的工具链。
