# 模型代码与结构说明

对应文件：`kan_swin.py`（模型主体）、`seg_swin.py`（编码器与归一化）、`stage47_i600.py`（损失）、`strict_env.py`（环境校验）

---

## 1. 这个模型是什么

`DeepKANSegSwin` —— 论文 **DeepKANSeg**（Kolmogorov–Arnold Network for Remote Sensing Image Semantic Segmentation）的一个**骨干替换变体**。

```
输入 1024×1024×3
   ▼
Swin-B 编码器（timm: tu-swin_base_patch4_window7_224，ImageNet 预训练）
   → 四级特征 [128, 256, 512, 1024] 通道
   ▼
DFR（DeepKAN 深度特征精炼）
   dfr_in: 1×1 Conv+BN  1024→256
   dfr_blocks: 4 × KANBlock(256)
   dfr_out: 1×1 Conv  256→1024（零初始化 → 热启动时恒等，稳定起步）
   → 残差相加回 res4
   ▼
GLKAN 解码器（KANDecoder：WF + FeatureRefinementHead + GLKANBlock ×2 + GlobalLocalAttention）
   ▼
9 类输出（含忽略类 0）
```

参数总量：**97.89 M**（实测自权重文件，按前缀统计）：

| 模块 | 参数量 | 占比 |
|---|---|---|
| encoder（Swin-B） | 86.74 M | 88.6% |
| DFR（dfr_in + 4×KANBlock + dfr_out） | 8.47 M | 8.7% |
| decoder（KANDecoder） | 2.67 M | 2.7% |

注意：四段微调只训练了最后那 2.67 M，**8.47 M 的 DFR 和 86.74 M 的编码器全程冻结**。

## 2. 与论文原版的差异（如实列出）

| 项 | 论文 | 本项目 | 影响 |
|---|---|---|---|
| 骨干 | ResNet-18 / ViT-B / ViT-L | **Swin-B**（timm ImageNet） | 精度更高、显存更大；论文未覆盖此组合 |
| DFR 结构 | DeepKAN 模块 | 沿用：`dfr_in` + 4 × `KANBlock` + `dfr_out` 残差 | — |
| 解码器 | GLKAN | 沿用：`KANDecoder` | — |
| KAN 基函数 | B-spline，G=5，r=3（论文 Table IX 的最优设置） | **同为 G=5，r=3** | 未偏离 |
| 输出类别 | 论文数据集各不相同 | 本任务 9 类（0 忽略 + 8 类） | — |

**结论**：KAN、DFR、解码器的**内部结构没有改过**；改的只有骨干，以及类别数。这条必须写清楚，因为它决定了"复现时该用哪份代码"。

## 3. 关键常量（不要改）

`kan_swin.py` 第 43 行起：

```python
class KANLinear(nn.Module):
    def __init__(self, in_features, out_features,
                 grid_size=5, spline_order=3,
                 scale_noise=0.1, scale_base=1.0, scale_spline=1.0,
                 enable_standalone_scale_spline=True,
                 base_activation=nn.SiLU, grid_eps=0.02, grid_range=(-1, 1)):
```

- `grid_size=5`、`spline_order=3` 与论文 Table IX 的最优点一致（论文里 G=3→5 提升 0.18 mIoU，r=1→3 提升 0.81，r=4 反而下降）。**这两个数不要动。**
- `dfr_out` 的权重是**零初始化**的，这是为了热启动时 DFR 保持恒等映射。如果复现时改成正态初始化，早期训练行为会完全不同。

## 4. 本阶段（四段微调）改了什么

**什么结构都没改，只做参数微调。** `train_decoder.py` 里：

```python
model = K.DeepKANSegSwin(K.NUM_CLASSES).to(dev)
model.load_state_dict(payload["ema"], strict=True)   # 严格加载，键不匹配就报错
model.eval()
```

`strict=True` 意味着权重与代码必须逐键对齐——这本身就是"结构没改"的证据。若有人改动了 `kan_swin.py` 的层名或形状，加载会立刻失败。

训练期间唯一被修改的状态是解码器参数，以及（可选的）EMA 副本。

## 7. 复现时最容易踩的两个坑

1. **`strict=True` 会在结构被改动时报错**——这是好事，别改成 `False` 去"让它跑起来"。一旦部分加载成功，分数会静默崩掉，还查不出原因。
2. **`dfr_out` 的零初始化**：如果从零重训，这个初始化必须保留；如果只加载权重做推理，它已经在权重里了，无需关心。
